# FlyBrain Research Platform v0.14.0

Integrated source release for **FlyBrain-NOS 0.13.3**, **URCAL 0.3.1**, and the **FlyBrain–URCAL Adapter 0.2.1**.

## Source archive

The complete source tree is distributed in:

`FlyBrain_Research_Platform_Fresh_Install_v0.14.0.zip`

The archive extracts to `FlyBrain_Research_Platform_v0.14.0/`.

## Quick start

From the repository root:

```bash
python -m zipfile -e FlyBrain_Research_Platform_Fresh_Install_v0.14.0.zip .
cd FlyBrain_Research_Platform_v0.14.0
python scripts/codespaces_bootstrap.py
```

The bootstrap script creates a local virtual environment, installs the project packages, runs the available tests, compiles modules, and performs import checks. It writes `SETUP_REPORT.json` and `SETUP_REPORT.md`.

For a manual test run in an environment with dependencies installed:

```bash
python -m pytest -q components/URCAL/tests
python scripts/run_stack_tests.py --flybrain components/FlyBrain-NOS --urcal components/URCAL
```

| URCAL | 0.3.1 | Provider-neutral compute abstraction, policy and quota controls, audit trail, catalog, and local durable queue |

## Scientific and operational boundaries

- Provider catalog entries are discovery metadata, not proof of live access, credentials, free quota, or successful external execution.
- The NeuroResearch integration is specification-only because its source/runtime and schemas were not supplied.
- FlyBrain's temporal/LIF components are synthetic engineering models, not biologically validated Drosophila simulations.
- The local SQLite queue is single-host durable storage, not a distributed queue.
- The included WSGI transport is a development interface, not a production-hardened public service.

Production use requires separately configured authentication, TLS, reverse-proxy hardening, rate limiting, managed secrets, backups, monitoring, and operational testing. No credentials should be committed to this repository.

See `FlyBrain_Research_Platform_v0.14.0/INSTALL_AR.md`, `SECURITY.md`, and `docs/RELEASE_AND_VALIDATION.md` in the extracted source tree for additional instructions.


## ChatGPT / FlyBrain integration

The production MCP gateway is hosted by Vercel at `https://flybrain-research-mcp.vercel.app/mcp`; it replaces the Cloudflare Worker as the active ChatGPT connection.

The repository-level integration provides:
- Source-labelled FlyBrain-NOS and URCAL project retrieval.
- Public web search, HTTPS page extraction, and multi-source evidence collection.
- A read-only MCP surface for the ChatGPT plugin, with per-instance rate limiting.
- A protected interactive Browser Use tool that remains inactive until a separate browser host and model runtime are configured.
- Plugin Creator package guidance in `CHATGPT_PLUGIN_SETUP.md`.

The ChatGPT plugin package `flybrain-zubaba` is at version `0.2.0` and points to the Vercel MCP endpoint. Its public connection does not contain the server bearer token. The service has been deployed to Vercel production and its root/health endpoints have been verified. The Vercel runtime currently reports public HTTP research as ready and interactive browser automation as not ready.

The Vercel serverless function downloads and verifies the pinned v0.14.0 release archive at runtime, then overlays the current bridge code. Its temporary filesystem is not durable storage. A separate persistent browser worker, model provider, browser profiles, scheduled monitors, and durable job queue have not yet been provisioned. No paid resources were created.

GitHub Actions currently fails before test steps start because jobs are not allocated a runner; therefore the Python test suite is not yet confirmed as passing. See `VERCEL_DEPLOYMENT.md` for deployment details and exact capability boundaries.

The bridge orchestrates research context and optional external model providers. It does not claim that the synthetic LIF runtime is a biologically validated Drosophila brain or that natural-language answers are generated by a biological connectome simulation.
